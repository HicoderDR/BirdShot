# 鸟类筛片 Demo

这是独立实现的本地研究原型，保留原有观鸟页面，在 `/cull` 增加筛片界面。修复版 `2026-11-14.4` 使用实际实例分割、多鸟对象选择与六点候选姿态；眼睛只是可选指标，默认不参与推荐。不上传用户照片，不删除、不移动、不改写原片；“淘汰”只是建议标签。

## 快速运行

需要 Node.js 22.12+（推荐 24）和 Python 3.12。Python 只用于一次性准备样例与模型，评分在浏览器本地运行。

```powershell
npm ci
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r scripts\culling-requirements.txt
.\.venv\Scripts\python.exe scripts\prepare-culling.py
npm run dev -- --host 127.0.0.1 --port 5173
```

打开 <http://127.0.0.1:5173/cull>，点击“分析这组照片”。首次加载两个本地 ONNX 模型约 50 MB；推理不上传照片。初始化脚本需要联网下载公开权重、约 10.5 MB 原视频和 6.39 MB 公开多鸟图片。模型、样例和工具目录已排除 Git。大照片的多局部精查在 CPU 上较慢，界面显示局部和实例进度；下载中断可重跑准备脚本续传，不将不完整文件当成功模型。

如果 Python 下载源不可达，可在确认镜像来源可信的前提下给 pip 指定可达的镜像；不要跳过 TLS 或文件哈希检查。已准备好的本机工作目录无需再次安装或下载。

当前已准备的 Windows 工作目录可直接运行 `.\scripts\start-culling.ps1`；如果全局 PATH 中没有 Node，它会使用本机工作区已准备的便携运行时。需要本地照片时运行 `.\scripts\start-culling.ps1 -PhotoDirectory (Read-Host "照片目录完整路径")`，仅扫描 EXIF 并启用回环地址的只读访问。

## 怎么体验

1. 按原帧顺序浏览真实斑鱼狗视频样例，或点击“公开多鸟图”查看真实雌雄绿头鸭单张图片。后者不是连拍。
2. 运行分析，分别开关鸟框、实际分割掩码和候选姿态点；每只鸟显示本帧实例编号与检测置信度。点击鸟框或实例按钮选择关注对象，已匹配的候选轨迹会联动其他帧。姿态只有喙、左右眼、头顶、左右肩部，未定义骨架，不画人体连线。
3. 查看原图、模型候选区域放大、分割主体内部纹理、同对象排名和建议依据。默认只比较主体指标；只有逐帧确认眼睛可见且候选位置正确后，才勾选允许候选眼区参与比较。模型可能对不可见眼睛给出高置信度，候选梯度不代表看到了眼睛或已经合焦。切换关注对象会清除眼区比较的确认。界面显示每阶段覆盖率与推理方式。
4. 导入自己的 JPEG / PNG；默认按**文件修改时间**粗分组，相邻最多 2 秒、整组最多 10 秒，并非 EXIF 拍摄时间。也可在分析前确认整批为同一连续组。一次最多 100 张，单张最多 80 MB / 6000 万像素。
5. 点击人工标签覆核。默认只在同一候选轨迹内比较，候选跟踪不是身份保证；如自动跟踪断开，可逐帧选好同一只鸟后明确勾选身份确认。导出 JSON 保存各实例的模型掩码 / 关键点、原始算法结果与人工标签，不包含用户照片像素。关闭页面前请导出。

“查看原图”打开原始分辨率文件；眼区放大仅用于预览，计算始终使用原始像素，不以缩略图评分。失败会明确显示，不把模型错误当失焦。只有全组分析完成后才能导出结果。

## 本机现有照片目录（可选）

不必复制整个相机目录。先只读扫描 JPEG / PNG 的 EXIF 原始拍摄时间与子秒，生成工作区私有清单；ARW 不加载。然后仅在回环地址启用只读、文件白名单端点：

```powershell
$photoFolder = Read-Host "输入本机照片文件夹的完整路径"
.\.venv\Scripts\python.exe scripts\prepare-local-photos.py $photoFolder
$env:BIRDSHOT_PHOTO_DIR = $photoFolder
npm run dev -- --host 127.0.0.1 --port 5173
```

在界面点“本机照片目录”，按下拉框选择**候选连续组**。间隔最多 2 秒、总长度最多 10 秒，支持相机 EXIF 子秒；相机时钟可能没有校准。只按时间不能保证同一主体，现有 ByteTrack 风格的 IoU / 运动关联用于候选匹配，可人工切换或确认；遮挡、快速运动和相似鸟会串号或断开，必须覆核。没有眼睛仍显示分割、可用姿态及主体技术指标。此目录访问仅限本机，不配置时不可用；不要为个人原片配置公网代理。静态部署没有这个端点，仍可手动导入。

本地清单在 `.tools` 中，个人原片和清单不加入 Git，不出现在公共样例或分享截图里。用户照片的分析和人工标签只在当前页面与用户导出的结果 JSON 中，关闭前请保存。

## 全目录顺序批处理：仅保存鸟体裁剪

原生 CPU ONNX 后台处理不依赖浏览器一直开着。逐组持久化并实时更新报告；仅保存每只检出鸟体的**原像素矩形裁剪**（带 5% 边缘、JPEG95 重编码）和小缩略图，不复制完整 JPEG 或 RAW。

严格选择复用同一 TypeScript 候选跟踪 / 组内比较策略。自动推荐仅使用分割主体内部梯度；检测置信度不足 50%、跨鸟匹配接近或可比对象不足的照片待审。**单张仍计算指标，但无绝对合焦校准时待审、不归档**，不会把自身归一化为 100% 就声称保留。被严格选中的关注鸟裁剪另外放入 `selected`，其余识别鸟体的裁剪仍留在 `crops` 供对比。

准备依赖与模型后，在工作区终端初始化一次：

```powershell
$python = ".\.tools\venv\Scripts\python.exe" # 或自己的 .venv
& $python scripts\batch_culling.py init --source (Read-Host "照片目录完整路径")
$job = (Get-Content .tools\batch-current.json -Raw | ConvertFrom-Json).job
```

在一个终端启动报告，在另一个终端启动实际处理：

```powershell
& $python scripts\batch_culling.py serve --job $job --port 5174
& $python scripts\batch_culling.py run --job $job --threads 4
```

打开 <http://127.0.0.1:5174/>。进度显示全部清点、完成组 / 照片、保留 / 待审 / 失败、当前阶段；点击完成组可查看各照片全部鸟实例裁剪、选择原因、主体指标、候选姿态与真实模型掩码。缩略图只来自鸟体裁剪；未检出鸟的组不伪造背景裁剪，可按需打开原图。报告仅允许回环主机与同源请求，不暴露其他目录。素材短期本机私有缓存，进度 JSON 不缓存。

输出是源目录旁的唯一 `BirdShot_Selection_日期时间_随机后缀`，不覆盖已有目录，也不重新扫描输出。结构：

- `crops`：所有检出鸟体裁剪与对应缩略图。
- `selected`：严格选中关注鸟的裁剪副本，写入后校验 SHA-256。
- `mapping.json`：裁剪 → 原图相对路径、源 JPEG SHA-256、配对 RAW 名称、原图尺寸、EXIF 方向、实际裁剪坐标、指标与选择依据。
- `groups`：各组完整实例、掩码、六点候选姿态、指标、失败原因和完成时间。
- `manifest.json` / `status.json` / `groups.json` / `report`：完整清点、模型与策略指纹、原子进度及报告入口。

坐标对应应用 EXIF 方向后的 JPEG 显示图，裁剪不缩放；派生 JPEG 不是 RAW 替代。RAW 同目录同名与 JPEG 配对，不重复当作第二拍；RAW-only 或其他未支持格式明确列未处理 / 待审。副文件单独清点。原图只读，处理前后检查尺寸 / 修改时间；记录原 JPEG 内容指纹。选择失败不计成功。

页面“请求安全暂停”在当前组结束后生效。再次对同一个 `$job` 执行 `run` 恢复；会先校验已完成原片、裁剪与模型 / 策略指纹，不能混用变更后的输入或版本。已完成组文件是权威提交，恢复会重建进度统计。异常硬终止留下 `run.lock` 时，应先确认旧进程确已停止，再移除这个任务的锁；不要同时启动两个处理进程。报告服务独立于处理进程，全量结束后仍可浏览。

原生 OpenCV 与浏览器 Canvas 的解码 / 缩放实现可能产生细小推理差异；Sobel、掩码内部像素与组内策略定义保持一致，有针对性的原生 / TypeScript 指标一致性测试。没有人工选片真值，保留只是技术候选，不是美学或绝对合焦判断。大量小目标需要局部精查，CPU 全目录任务可能运行较久。

结束后执行 `& $python scripts\verify_batch.py --job $job`，核对逻辑项无重复遗漏、原 JPEG SHA-256 / 全部原片尺寸与修改时间、裁剪尺寸与 SHA-256、严格单张待审、selected 集合和最终计数，并生成 `verification.json`。任务未结束时该命令明确拒绝声明完成。

## 流程与保守规则

旧版使用 YOLO11n nano 整图 640×640：6192×4128 照片中的远鸟缩小后只剩少量像素，且“必须单鸟、眼睛可测、至少三帧”的硬门槛使正常多鸟 / 无眼照片整组待审。不是未启用 YOLO 或下载失败后的替代算法。

修复版使用官方 **YOLO11s-seg**（COCO bird 类 14），最终实例检测阈值仍为 0.35。全图 640×640 letterbox；大图目标不足时增加原图 2048 像素局部推理，并在候选附近使用 512–1536 原像素区域精查。0.15 仅生成待精查候选，不能直接变成可靠实例。各局部框与掩码映射回原图，过滤局部边缘截断框，跨局部 NMS 去重。

分割采用模型实际输出的 32 通道、160×160 原型与每个实例的掩码系数，经过 letterbox / 局部坐标逆变换后显示半透明掩码和轮廓。不是检测框、椭圆或启发式填充。原型分辨率有限，轮廓是栅格预测，不是精细羽毛边缘真值。无有效掩码会明确报告，不冒充成功分割。

每只检出的鸟分别裁取带边缘的主体区域，用 `synthet/eye-pose-v0` 定位六个模型定义点。模型卡和固定版本 YAML 明确顺序：喙、左眼、右眼、头顶、左肩、右肩；该模型不是通用鸟体骨架或翅膀 / 尾巴姿态模型。只画置信度 ≥65% 且在图内的候选点；眼部可见性矛盾时不画该眼点，表格明确标注不确定。高置信度也可能误定位，须看原图。没有姿态不影响已有分割。

原图眼区半径由喙眼距离估计（8–32 像素），以灰度 Sobel 横纵梯度平方和的均值作为 Tenengrad。没有眼睛、低置信度、小主体、越界或喙点不可靠时，眼部指标未判定，不否定整个鸟实例。还要求可见性明确：另一眼要么明确隐藏（置信度 ≤20%），要么两眼均可靠可见（≥65%）；中间状态视为可能背向或误定位。这仍是保守启发式，不能保证眼点正确。头部或主体指标不会冒充眼睛分数。

另外单独测量**分割主体内部的原像素 Tenengrad**，排除背景及跨分割边缘的 Sobel 核。它衡量主体内部纹理 / 技术细节，受姿态、羽毛、噪声、曝光影响，**不是眼部合焦判断**。眼睛不可见和多鸟不再阻断这一指标。

同对象至少 **2 帧**即可产生透明的候选比较，不强行做所有鸟的总榜。候选跟踪断开或默认关注鸟不匹配时，可逐帧选择同一对象，不会因为恰好两帧就禁止比较。**眼区默认不参与推荐**；人工覆核并启用后，才额外限制喙眼尺度和朝向。不够时单独比较主体指标。相对最佳 ≥80% 优先保留候选；**主体指标和两帧比较从不自动淘汰**。仅人工允许的 3+ 可比候选眼区帧的 <35% 会标记建议淘汰，仍需覆核。这不是合焦真值，无眼、多鸟不是淘汰理由。

## 限制与验证

没有人工选片偏好、眼部合焦真值或真实相机 RAW 连拍评测，不能声称算法准确率已经验证。近景、单只、相似姿态的小段视频不能代表野外远鸟、多主体和不同镜头。JPEG / PNG 支持，不支持 RAW。导入粗分组不是可靠的摄影时间分组，位置相似也不是物种或个体身份保证。

```powershell
npm run test:culling
npm run build
npm run lint
```

针对性测试覆盖局部模糊、可见性矛盾、两帧比较、不串对象、原型掩码坐标逆变换、分割内部排除背景、无眼多鸟的独立主体指标与分组长度上限。真实视频、公开多鸟图和实际浏览器推理应单独检查，不能用合成测试代替真实评测。

已启动本地服务、准备模型后，可以运行 `npm run test:demo`，使用本机 Microsoft Edge 验证实际浏览器推理、文件导入、人工标签、损坏图像错误和手机布局，生成公开视频样例的截图、JSON 和独立 HTML 报告。其他平台需先通过 Playwright 安装浏览器，并指定 `BIRDSHOT_BROWSER_CHANNEL`。默认不读取个人目录；显式设置 `BIRDSHOT_LOCAL_GROUPS`（如 `local-1,local-2`，对应界面候选组号）才验证指定的少量本机组，组内最多 20 张。

实际运行的阶段覆盖率和建议数量须按对应修复版结果解释；旧版三组 16 帧仅 4 帧检出鸟体、1 帧可测眼区、0 帧参与比较。修复版的逐阶段统计、公开可视化与匿名结果摘要由浏览器验证脚本生成。所有个人原片只读，分享产物仅包含明确授权的公开样例，不是带真值的准确率评测。

本次已实际验证四个本机候选连续组共 **18 张 JPEG**：11 帧有鸟体、33 个模型分割实例、29 个实例有高置信度候选姿态点、6 帧参与同对象比较，产生 **4 张保留候选、14 张待审、0 张淘汰**，这些推荐均依据主体内部纹理而非眼部合焦。原来的同一批 16 帧鸟体覆盖从 4 帧提升到 9 帧。二帧多鸟组仍因对象未稳定匹配而待审，不再因“没有第三帧”拒绝比较。18 张原片哈希保持不变。公开双鸭图实测两实例掩码及对象切换；36 个真实视频连续帧实测分割 / 姿态 / 原像素指标，受控候选眼区模糊后的梯度约为原来的 16.4%。
